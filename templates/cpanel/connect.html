Scripts and runs

A token with scripts:read, runs:read and runs:output can list scripts, read a run with its result and fetch its output. Script code is never returned; output comes with secrets masked, exactly as the run page shows it. Bind the token to one script to limit it to that script and its runs. API and MCP callers see who started a manual run by user id only, never the email.

Add scripts:run to start a script with inputs, and runs:stop to stop a run. With "wait": true the call waits up to 55 seconds and returns the result; a run still going comes back with HTTP 202 and its id, to poll with runs.get. Every run and stop, and every failed call, is listed on the token's Activity page.

Claude Code

Add the MCP server above with that token, then ask. The tools are scripts-list, scripts-get, scripts-run, runs-list, runs-get, runs-output and runs-stop.

claude "List my PyRun scripts, then show the stderr of the last failed run and explain the error."

REST

curl -H "Authorization: Bearer YOUR_TOKEN" "{{ api_url }}/scripts.list?q=report"
curl -H "Authorization: Bearer YOUR_TOKEN" "{{ api_url }}/runs.list?status=failed&limit=5"
curl -H "Authorization: Bearer YOUR_TOKEN" "{{ api_url }}/runs.get?run=RUN_ID"
curl -H "Authorization: Bearer YOUR_TOKEN" "{{ api_url }}/runs.output?run=RUN_ID&stream=stderr&tail=4000"
curl -H "Authorization: Bearer YOUR_TOKEN" -H "Content-Type: application/json" -d '{"script":"SCRIPT_ID","inputs":{},"wait":true}' "{{ api_url }}/scripts.run"
curl -H "Authorization: Bearer YOUR_TOKEN" -H "Content-Type: application/json" -d '{"run":"RUN_ID"}' "{{ api_url }}/runs.stop"

runs.output answers with plain text over REST (stdout unless you pass stream=stderr); output is written when the run ends.

Scripts as tools

Turn on Expose as MCP tool in a script's editor and give it a tool name. An MCP client connected with a token that holds scripts:run then lists the script as a tool of its own: the script's inputs are the tool's parameters, and calling the tool runs the script and returns its result (what it passed to pyrunner_run.set_result()).

The call waits up to {{ tool_wait }} seconds for the run to end. A run still going then comes back with its run id, as does a call made while every wait slot is taken; give the token runs:read too, so the client can poll runs-get. Tool calls count against the same 30 calls a minute as scripts.run, a token bound to one script sees only that script's tool, and disabled scripts aren't listed. Clients read the tool list when they connect: reconnect after exposing a script.

Claude Code

Add the MCP server above, then run /mcp in Claude Code to see the tools. A script exposed as weekly_report shows up as mcp__pyrun__weekly_report; ask for it by what it does:

claude "Run my weekly_report tool for Paris and summarise what it returned."
